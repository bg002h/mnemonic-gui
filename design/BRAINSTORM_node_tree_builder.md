## 0. Ground truth (all verified at the consult; re-grep at SPEC time)

1. The GUI runner is argv-only with `stdin(Stdio::null())` (`src/runner.rs:93`); the toolkit's `--spec -` reads stdin (verified live).
2. GUI subprocess output is display-only today (`main.rs:322-339`, `from_utf8_lossy` → labels); envelope parsing exists only in tests.
3. The failure envelope is one-struct parseable: `{"diagnostics":[{node_path, kind, message, flag?}]}` (item struct `gate.rs:74-85`; envelope `cmd/build_descriptor.rs:367`; exit 2 `:326-327`). **R0-r1 C2: exit 2 does NOT imply an envelope** — spec-parse errors (every partially-built tree!) and unsupported schema_version exit 2 with EMPTY stdout + stderr text (`error.rs:503` BuildDescriptorSpec is exit-class 2). The parse contract is therefore: stdout parses as `{diagnostics:[…]}` → node-addressed view; otherwise surface stderr in the global error strip.
4. **`descriptor_builder` is toolkit-binary-PRIVATE** (`main.rs:12`, not in lib.rs) — no in-process `PolicyNode` reuse without a toolkit lib-promotion release; rejected for v1.
5. Path grammar (toolkit `gate.rs:563-589` `child_paths` + `:232` key paths): `root`; `{path}.{kind}[i]` (binary + andor); `{path}.thresh.subs[i]`; `{path}.wrap.sub`; `{path}.{kind}.keys[i]` (multi/sortedmulti keys). `"params"` sentinel exists (preset-mode; unreachable in spec mode — the mapper must fail-soft, not crash).
6. 17 node kinds, only **9 payload shapes** (R0-r1 I1) in `--spec-schema`'s `nodes` section (toolkit `schema.rs:26-44`): `string(key)`, `{k:uint, keys:[key]}`, `uint`, `string(hex64)`, `string(hex40)`, `[node, node]`, `[node, node, node]`, `{k:uint, subs:[node]}`, `{w:string, sub:node}`.
7. `--emit-spec` emits the lowered gate-validated spec JSON for archetype params (the engine's lowering — the single source of truth).
8. `FormState` persists; no `deny_unknown_fields` → an additive field is persistence-compatible without a schema-version bump.
9. The gate's complexity envelope (`DEFAULT_PREVIEW_CAP` 4096, `gate.rs:33`) bounds **keys+hashes ≤ ~12** (exact math from `check_cap`) — but NOT node count or depth (a depth-16 timelock chain passes exit 0 — R0-r1 I2 probe). REALISTIC trees stay small (the keys are the expensive part), which still carries the inline-UI choice; the §3 GUI-side recursion-depth cap is therefore LOAD-BEARING (serde_json's 128-level default is the toolkit's backstop, not the GUI's), and the SPEC adds a node-count/depth UI posture for pathological-but-valid trees.

## 1. Locked decisions (consult-ranked; provenance per §0)

1. **Scope: the FULL 17-kind grammar**, data-driven from a GUI-static `NODE_KIND_SPECS` mirror of the `nodes` section (kind + payload-shape discriminant + arity). The 9-shape fact makes the "rare" kinds ~free (they reuse arms the common kinds need); `wrap` is NOT optional (every `and_v` left arm needs `v:`); a subset would break `--emit-spec` import + the mirror gate. The payload strings are a closed vocabulary matched EXACTLY (the archetype-kind-vocabulary precedent) — never structurally parsed at runtime.
2. **UI paradigm: inline indented tree** (`CollapsingHeader`/`ui.indent` + `push_id(node.id)`): per-node kind ComboBox (17 + an unset `"(choose…)"` sentinel), payload widgets by shape, fixed-arity children auto-materialize as unset placeholders on kind selection, `thresh` gets add/remove branches. No inspector panel (the §0.9 envelope keeps trees small), no drag-and-drop in v1 (reorder = remove+re-add). JSON-text-editor rejected (it IS the thing the wizard replaces).
3. **Data model: GUI-owned "wide node"** (`src/form/tree_model.rs`): `TreeState { enabled, next_id, root }`, `TreeNode { id: u64, kind: String, key, k, keys, n, hex, w, children }` — all payload fields coexist so kind switches never destroy data; emission projects only the active kind's fields. Lives in `FormState` as `#[serde(default)] tree: Option<TreeState>` — **persisted** (xpubs are watch-only, slot rows already persist) — with one REQUIRED hygiene extension: `redact_for_persistence` blanks key fields matching the xprv prefix heuristic (toolkit `gate.rs:281` — bytes 1..4 == `"prv"` after stripping `[origin]`; verified GUI-reusable incl. Yprv/tprv-with-origin — R0-r1 M1) + a live amber hint. Hashlock hex fields are deliberately NOT redacted (digests are public commitments; preimages never enter the spec — considered and rejected, R0-r1 M2). `FormState` has no `Clone` — the redaction fn's field-by-field struct literal is the compile-time forcing function for wiring the tree field; name it in the SPEC. Node `id` = stable egui identity (survives sibling removal); diagnostics map by PATH, computed fresh per frame.
4. **Path generation mirrors the toolkit gate EXACTLY**: one pure `child_path(parent_path, kind, child_index)` implementing the five productions, unit-pinned against literal strings (R0-r1 I3: the toolkit gate tests carry `root.or_d[1].and_v[0].wrap.sub` etc., but NO `thresh.subs[i]` literal exists toolkit-wide and `keys[i]` lives in its CLI tests — the GUI authors its own literals; the LIVE parity gate (§1.8.ii) is the real tether, and the consult-probe validated all five productions deep-nested: `root.thresh.subs[2].andor[2].multi.keys[0]`).
5. **Spec delivery: stdin** — a ~15-line `run_with_stdin(argv, Option<Vec<u8>>)` runner extension (`Stdio::piped()`; existing `run` delegates with `None`, zero behavior change; **discipline R0-r1 I6: `write_all` → explicitly DROP the `ChildStdin` → `wait_with_output`** — the toolkit reads to EOF, an undropped handle deadlocks every run; tolerate `BrokenPipe` on the write (child exits pre-EOF on clap errors) by degrading to collect-output; the skip-threaded-writer license is the size assumption: a max-envelope spec is ~2 KB ≪ the 64 KiB/4 KiB pipe buffers — state it); tree mode appends `--spec -` and pipes the generated JSON. No temp files (no lifecycle/cleanup/disk-artifact story). The stdin capability is also the missing substrate for the filed `boolean-stdin-secret-toggles-never-emit` class. Copy story: a "Copy spec JSON" button; the generic argv-Copy buttons are ANNOTATED or suppressed in tree mode until the P3 pipeline-form copy (`--spec -` pasted bare into a shell hangs on terminal stdin — R0-r1 M4).
6. **Validation round-trip IS v1**: a tree-mode "Validate" button runs `build-descriptor --spec - --json`; exit 0 → descriptor + cost summary; **stdout-parses-as-envelope** (NOT exit-code-keyed — §0.3/C2) → parse `diagnostics`, tint matching node headers + show messages under rows; non-envelope failure (spec-parse error, version skew, clap error) → stderr in the global error strip; unmatched `node_path` (drift, `"params"`) → the strip too, fail-soft. **Diagnostic lifetime (R0-r1 I4): any tree mutation CLEARS the parsed diagnostics** (sibling removal shifts `[i]` indices — a stale tint on the wrong node is a funds-tool correctness bug); storage location + `last_run` interplay → SPEC. This is the GUI's first runtime stdout-parse (~40 lines + cells) — proportionate; node-addressed diagnostics were built FOR this consumer. The generic Run button stays untouched.
7. **Mode: GUI-side third mode** (`TreeState.enabled`, NOT a pseudo-flag): the build-descriptor form gains an explicit mode selector (Generic/spec-file · Archetype · Tree builder); `conditional::build_descriptor` extends — tree enabled ⇒ `--spec` AND `--archetype` Disabled **AND all TEN `requires = "archetype"` flags Hidden — the 9 params PLUS `--emit-spec` (R0-r2 I-1: a stale checked `--emit-spec` Boolean emits the bare flag, clap-fails with `--archetype` suppressed, and conflicts with Validate's `--json`) (R0-r1 C1: Disabled on the two mode flags alone does NOT stop declared param values from emitting — they'd ride argv with `requires = "archetype"` unsatisfied and clap-fail every tree-mode run)**; the render dispatch is also mode-aware (the archetype param form must not render in tree mode — `active_archetype` alone reads only the dropdown). **"Edit as tree" from archetype mode: include in v1 as the LAST phase, explicitly cuttable** — runs `--emit-spec`, parses via the spec-JSON→TreeNode deserializer (needed anyway for goldens/import), populates the tree, switches mode. NEVER re-implement lowering GUI-side.
8. **Three drift gates** (all skip-if-absent integration posture, the `archetype_schema_mirror` pattern): (i) `spec_nodes_mirror` — `NODE_KIND_SPECS` vs the binary's `nodes` array (kind set+order, payload verbatim) + refuse-loud pins on **BOTH** `spec_schema_version == 1` (the grammar axis the mirror copies — R0-r1 I5) and `supported_doc_schema_version == 1`; (ii) **path-grammar parity (the keystone)** — plant errors covering the path grammar exhaustively — the 4 `child_paths` arms (binary/andor merged-form, `thresh.subs[i]`, `wrap.sub`) + `root` + the `keys[i]` production, using a keys-CLASS error (e.g. `secret_key`) for the latter since node-level key errors attach to the NODE path (R0-r2 M-3 normalization), run the REAL binary `--spec - --json`, assert every returned `node_path` equals the GUI-computed path; (iii) spec round-trip goldens — vendor the 5 toolkit archetype fixtures (immutability is CYCLE-scoped in the presets SPEC — the live exit-0 leg of this gate is the staleness tether, R0-r1 M3); `from_spec_json → TreeNode → to_spec_json` value-identical + each runs exit-0 through the binary.
9. **One GUI MINOR (v0.32.0), three phases, P3 cuttable** (to a v0.32.1 if long): P1 model+contracts (UI-free, fully TDD-able): NODE_KIND_SPECS + mirror gate, TreeNode/TreeState + (de)serializers + completeness check, child_path + pins, golden round-trips, persistence field + xprv redaction. P2 the form: run_with_stdin; lib-hosted `tree_form.rs` (main.rs dispatch-only — the archetype_form seam); mode switch + conditional; Validate + highlight; Copy; kittests + the parity cell. P3: "Edit as tree" + copy polish.

## 2. Top risks the SPEC must nail

1. **Path-grammar parity incl. `multi.keys[i]`** — the only contract with no compile-time tether (gate ii is mandatory).
2. **xprv-in-persisted-tree hygiene** (the §1.3 redaction extension + hint; never persist secret material).
3. **Stale-value leakage across THREE modes** (the mutex matrix grows; visibility-suppression — Disabled OR Hidden, both argv-suppressing — must cover every pairing incl. the 10 `requires=archetype` flags).
4. **Version skew**: a PATH binary < v0.50.0 has no `build-descriptor`; pinned-version soft-check posture + graceful Validate failure.
5. Kind-switch/arity-change child policy (lean preserve-and-flag, the v0.31.0 data-preservation ethos) — SPEC decides the exact matrix.
6. Whether kittest can drive the kind-picker ComboBox (check early; the dropdown_id_salt precedent).

## 3. Left to the SPEC

Exact `TreeNode` serde shape + kind-switch preservation matrix; arity-change child policy; unset-placeholder semantics + incomplete-tree messaging (GUI-side block vs CLI refusal); the wrap `w` affordance (free text + hint vs a dropdown of `a s c d v j n l u t`); per-shell copy formats; no-matching-node diagnostics display; the schema-v2 refusal UX; a defensive recursion-depth cap; kittest drivability of the kind ComboBox.
