## 1. I5 design — secret positionals never persist, by TYPE

Follow the v0.31.1 repeating-secrets precedent: secrets live in `state.secret_widgets` (`BTreeMap<String, Vec<SecretLineEdit>>`, `#[serde(skip)]` — the never-persist invariant holds by type), not in redaction arithmetic.

1. **`PositionalArgSchema.secret: bool`** + the 20 literal sites (5 `true` per §0 census, 15 `false`). Doc-comment mirrors `FlagSchema.secret`'s.
2. **Render** (`main.rs` positional loop): `pos.secret` → per-row `SecretLineEdit` rows stored under key **`"positional:<name>"`** in `secret_widgets` (the `positional:` prefix is collision-proof — flag keys all start `--`; bare positional names like `"ms1"` could collide with nothing today but the prefix makes it self-evident). Keying verified safe (R0-r1): every `secret_widgets` consumer does exact-key lookup (`invocation.rs:257`, `widget.rs:102/:133`, `has_value` `mod.rs:380`); nothing iterates the map against flag tables; the zeroize sweep flattens `values_mut()` so the new keys ride it. **Widget seam (R0-r1 M7): do NOT bend `flag_is_secret`/`render_with_dispatch` (both `FlagSchema`-coupled)** — call `SecretLineEdit::show` directly in the positional loop, replicating the required-seed / `+ add` / `✕` chrome keyed off `pos.required`/`pos.repeating`. `repeating: true` (`shares`) gets the v0.31.1 multi-row add/remove UI; non-repeating gets one row. Non-secret positionals keep the current `state.positionals` path untouched. Paste-warn parity is moot — `should_warn_on_paste` is FlagSchema-keyed and not live-wired anywhere today. Give `FormState.positionals`'s doc (`mod.rs:281-284`) a lockstep sentence. New invariant to record (R0-r1 M2, verified: `has_positional`'s only 2 callers are the non-secret md template/phrases conditionals; Run is not gated on required positionals): **`has_positional` is permanently false for secret positionals** — a future conditional over one must consult `secret_widgets["positional:<name>"]`.
3. **Assemble** (`invocation.rs`): for the subcommand's secret positional (≤1 by §0), emit non-empty `secret_widgets["positional:<name>"]` rows at the positional position (argv end, where `state.positionals` emits today); non-secret path unchanged. A values-style stale `state.positionals` entry for a secret positional is IGNORED (the widget path is authoritative) — mirrors the v0.31.1 kind-gated assembler discipline.
4. **Belt — redaction arm** (`persistence.rs`): since `redact_for_persistence` cannot know the subcommand, the belt is unconditional: **drop ALL `state.positionals` content at persist** (`positionals: Vec::new()`). Cost: non-secret positionals (md1/mk1 strings, a template, an address) don't survive a restart — they are cheap re-pastes, persistence is unwired today, and several are backup-material strings a privacy-conscious user plausibly does NOT want on disk anyway. Fail-closed beats name-plumbing a subcommand context through the redaction layer. (If Phase-8 later wants non-secret positional persistence, it can thread the subcommand and narrow the arm — record as a non-blocking note in the FOLLOWUPS resolution.) Serde-shape compatible: no `SCHEMA_VERSION` bump (`persistence.rs:34`, =1) and no `state.json` exists in the wild — `save`/`load` (`:168`/`:185`) have no `src/` callers (R0-r1 M6).
5. **`should_confirm_run`**: add a positional loop — any `subcommand.positional_args` entry with `secret: true` whose `secret_widgets["positional:<name>"]` rows contain a non-empty value → `true`.
6. **Zeroize**: `secret_widgets` rows already sweep on exit (v0.2 B.1 invariant) — the reserved-key rows ride the existing sweep; no new code, but T-cell asserts it.

## 2. I6 design — tree key/keys persist-redaction flips to a POSITIVE allowlist

Replace the persistence walk's deny-list (`blank_xprv_keys`) with **`blank_non_extended_public_keys`**: clear every `key` / `keys[i]` entry (recursive, incl. surplus children) **unless** the origin-stripped part (`rsplit(']')`, the existing idiom) matches the **full 4-byte literal prefix list** `xpub/tpub/ypub/Ypub/zpub/Zpub/upub/Upub/vpub/Vpub` (R0-r1 I2: a bare "`pub` at bytes 1..4" probe leaves byte 0 unconstrained — base58 contains p/u/b, so a `Kpub…`-form WIF would survive in cleartext; the deny-list's identical looseness was safe because over-blanking is harmless, but in the allowlist direction the failure cost inverts to a persist leak. The literal list's first chars {x,t,y,Y,z,Z,u,U,v,V} are disjoint from WIF's {K,L,5,9,c}). Use the panic-free `as_bytes().get(..4)` idiom (R0-r1 M8). Over-acceptance note for the fn doc (R0-r2 M-r2-3): the list admits SLIP-132 forms (`ypub`/`zpub`/`Upub`…) the toolkit's step-2 `Xpub::from_str` would refuse anyway — correct trade (public material, no leak direction; future-proofs SLIP-132 intake). Do NOT later "tighten" to {xpub,tpub} (back-door behavior change) or mistake the allowlist for a validity check.

- **What this catches that the deny-list missed:** WIF (`K`/`L`/`c`/`5`/`9` base58), raw-hex private keys, and any garbage — all blanked.
- **The documented fail-closed cost:** a raw-hex x-only/compressed PUBLIC key is byte-shape-indistinguishable from a raw-hex PRIVATE key (the very reason the toolkit refuses to prefix-classify hex) — the allowlist blanks BOTH. A legit hex pubkey doesn't survive persist; xpub-form keys (the GUI's dominant input) do. This is the right trade for a persist path with no `from_str` backstop.
- `is_xprv_like` is NOT deleted: `tree_form.rs:779`'s live render-side advisory keeps it (warn-the-user-now semantics, where false-negatives are tolerable because the persist walk now fails closed). Its doc-comment gains a "persist-redaction uses the POSITIVE allowlist, not this" pointer, and the `xprv_hint` prose (`tree_form.rs:778-787` "this value will not be saved") gets the R0-r1 M3 widening note — the not-saved set now includes WIF/hex/garbage with no hint fired; name the silently-blanked classes in the doc (render-side hint extension itself = non-blocking, out of scope).
- `rsplit(']')` caveat (R0-r1 M4, pre-existing in `is_xprv_like`): everything before the LAST `]` goes unexamined (`xprv…]xpub` keeps the whole string) — document at the new fn; tightening the origin-shape check is optional, not required for this cycle.
- Rejected alternative (recorded): option (b) "refuse to persist an ungated tree" couples persistence to transient Validate state (`validate_ok` is `#[serde(skip)]` and cleared by `mark_dirty`) — a user mid-edit would silently lose the whole tree; the allowlist preserves structure and blanks only key material.
