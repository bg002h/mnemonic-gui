## MINOR
- **M1 — No render/no-panic smoke cell exercises build-descriptor's form.** The full-suite pass validates the SCHEMA + argv-assembly + drift-gate layers; no kittest/render cell touches build-descriptor (`default_form_state.rs` covers only `bundle`; `widget_interaction.rs` D.4 and `xpub_search_widgets.rs` render-no-panic cells target other specific subcommands). The form is nonetheless sound **by construction**: the widget renders by `FlagKind`, not by subcommand (`src/form/widget.rs::render_flag` dispatch + defensive `_ =>` arm at `widget.rs:378`), and build-descriptor uses only `Path`/`Boolean`/`Dropdown`, all of which already render on other subcommands' live forms. The `xpub_search_widgets.rs` precedent added exactly such cells for its new subcommands — the SPEC's optional RED test (§5) already pins `--spec` `kind`, which is the load-bearing part. Recommend the implementer either add one `build_descriptor_renderer_no_panic` cell (cheap, mirrors the xpub_search precedent) or explicitly record in the cycle that form-render is sound by-construction. Non-blocking.
- **M2 — State the default-form emission explicitly.** With `default_value: None` (SPEC §3b), `--format` and `--network` seed via `default_flag_value_for(kind)` → `opts.first()` (`src/form/widget.rs:133-135`, reached because line 167-168 falls back when `default_value` is `None`). So the default build-descriptor form emits `--format descriptor --network mainnet`. Both are valid invocations (`--format descriptor` = the bare concrete descriptor; mainnet = the toolkit's own default), and the behavior is **identical to every existing `--network`/`--format` Dropdown** (e.g. import-wallet `--format`, the `--network` convention at `mnemonic.rs:392-399`). Established convention, not new behavior — but the SPEC should say which so a reader isn't surprised the default form is non-empty. Non-blocking.
