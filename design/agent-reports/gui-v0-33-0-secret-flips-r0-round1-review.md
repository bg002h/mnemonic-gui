## Important

**I1 — Phase 1's gate-verification claim is mechanically wrong, with a live false-green path on this machine.**
SPEC §7 Phase 1: "confirm `schema_mirror_secret_drift` RED on exactly the 9 pairs **(now via the PINNED dep path, not just MNEMONIC_BIN)**". The gate has no pinned-dep path. `tests/schema_mirror_secret_drift.rs:56-58` resolves the binary as `MNEMONIC_BIN` env-var else bare `mnemonic` on `$PATH`; the Cargo dep (`mnemonic_toolkit::secret_taxonomy`, `src/secrets.rs:34`) feeds only the NodeType/SlotSubkey constants, which are byte-identical v0.52.0→v0.53.1 (verified: `git diff mnemonic-toolkit-v0.52.0..v0.53.1` touches only the toolkit's `secrets.rs` flag list, not `secret_taxonomy`). So the pin bump changes NOTHING about what the local gate sees. Worse: the actual `$PATH` binary here is `mnemonic 0.24.0` (`~/.cargo/bin/mnemonic`), which is pre-v5 — `fetch_v5_schema` returns `None` and the cell **silently passes by skip** (`tests/schema_mirror_secret_drift.rs:74-82`; this is the filed minor `secret-drift-gate-version-skip-silent`). An implementer following Phase 1 as written, without `MNEMONIC_BIN`, gets green-by-skip where the spec demands RED — the phase gate inverts. Fix: Phase 1 must mandate `MNEMONIC_BIN=<locally built v0.53.1 binary>` for the RED confirmation (and state that the pin bump's gate effect is CI-only, via `pinned-upstream.toml:22` → the `install-mnemonic-toolkit` step in `.github/workflows/schema-mirror.yml:49-62`).

**I2 — three deterministic test breaks are left as a "may break" risk; enumerate them and pin the fix shape.**
SPEC §8 risk (b) says kittest/snapshot cells "**may** pin the old unmasked widget for `--phrase` — fix forward in-cycle". The breakage is not speculative and it is not widget-side: `tests/xpub_search_widgets.rs` has 3 argv-assembler cells that push `--phrase` into `state.values` and assert emission — `cell_path_of_xpub_argv_assembles` (:46, assert :75-:76), `cell_account_of_descriptor_argv_assembles` (:117, assert :144), `cell_passphrase_of_xpub_argv_assembles` (:263, assert :290). After the flip, `assemble_argv`'s secret branch consumes Text secrets from `secret_widgets` and `continue`s — a values-synthesized Text-secret entry emits NOTHING (`src/form/invocation.rs:255-273`, exactly the documented "values-synthesized Text-secret entry emits NOTHING" arm). All 3 go RED in Phase 2, guaranteed. The spec should name them and prescribe the conversion — seed `state.secret_widgets` with `SecretLineEdit::from_text(...)` (public, `src/form/secret_widget.rs:55`; live pattern at `tests/repeating_secret_rows.rs:210-218`) and keep asserting `--phrase <value>` emission — so the implementer doesn't "fix" by deleting the emission assertions. Converted, they double as the T2/T3-adjacent positive cells for the new path. (Everything else survives by construction: conditional/visibility cells route through `FormState::has_value`, which reads both `values` and `secret_widgets` — `src/schema/mod.rs:378-385`; `tests/xpub_search_schema_mirror.rs:163-201` asserts only secret=**true** expectations; the union census cells in `tests/repeating_secret_rows.rs:289-360` are field-extracted, count-free.)
